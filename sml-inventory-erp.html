01 / Overview

Bringing stock activity into one operating view.

The system brings item records, stock movement, supplier information and operational reports into a single browser-based workflow. Its documented design keeps transaction history and audit records separate from the main inventory master.

CAPABILITY 01

Item master

Organizes items by category, type, color, thickness, page, unit and alarm quantity.

CAPABILITY 02

Stock movement

Records Stock In, Stock Out, Stock Return and Stock Adjustment with reference information.

CAPABILITY 03

Supplier records

Maintains supplier information alongside inventory and transaction workflows.

CAPABILITY 04

Operational reports

Includes transaction, item-wise, category-wise, type-wise, ledger, supplier and low-stock reports.

CAPABILITY 05

Excel workflows

Supports Excel export and bulk Stock In import with validations for dates, quantities, item references, duplicates and suppliers.

CAPABILITY 06

Audit & backup

Includes an audit trail plus JSON backup and restore options for operational continuity.

03 / Architecture & controls

Structured data with access boundaries.

Firebase data structure

  • erp/main — inventory master, settings, suppliers, sequences and item metadata.
  • erp_txns — stock movement transaction records.
  • erp_audit — audit records.
  • roles — user access mapping.

Data integrity practices

  • Stock movement writes use Firestore transactions to re-read current stock before committing.
  • Stock adjustment is recorded without deleting history.
  • Bulk import validates key fields before committing an upload.
  • Firestore rules protect the canonical inventory document from ordinary-user deletion.
The repository documents Firebase Authentication and Cloud Firestore. This page describes the documented project capabilities; it does not expose business records, login credentials or private operational data.
